## 1. アプリ概要

### DipTriageとは

**DipTriage** は、株価が急落した銘柄を自動で収集・分析し、「これは一時的な事故なのか、それとも回復困難な事件や構造問題なのか」を判断する材料を素早く提供する、**投資判断補助ツール**です。

### 誰のためのツールか

株式投資家が対象です。特に以下の状況で有用です：

- 多数の銘柄を監視しており、急落のたびに個別調査するのが負担な方
- 「この急落は買い場か、撤退すべきか」の判断に時間がかかっている方
- LLMを活用したいが、判断根拠の透明性が欲しい方

### 何を解決するか

株価が急落したとき、投資家は以下を素早く判断しなければなりません：

1. 急落の**原因**は何か（ニュースを探す）
2. その原因は**一時的**か、**構造的**か（定性分析）
3. **数値的に異常**な動きがあるか（定量分析）

これらを手作業でやると1銘柄あたり30分〜1時間かかります。DipTriageはこのプロセスを自動化し、**数分でブリーフィングを提示**します。

### AIの役割

DipTriageのAIは**「買え」「売れ」とは言いません**。

AIの役割は、分析根拠・分類の理由・反証・類似ケースを整理した**ブリーフィング（説明書）を提示すること**です。最終的な投資判断は、常にユーザー自身が行います。

## 2. ユーザーができること

### 自動処理（ユーザー操作不要）

以下は、設定した時刻に自動で実行されます：

| 処理 | 内容 |
|------|------|
| **急落銘柄の検知** | 対象市場の全銘柄から、前日比 -5% 以上の銘柄を抽出 |
| **マクロ除外** | 市場全体が大きく下落した日（指数 -2% 以上）の銘柄は「マクロ要因」フラグを立て、個別分析の優先度を下げる |
| **数値分析** | 出来高異常度・ボラティリティ・β値・セクター相対パフォーマンス・PER/PBRを自動算出 |
| **ニュース収集** | Yahoo Finance RSSから関連記事を自動取得し、急落前・急落後・同日で分類 |
| **問診（初期AI分析）** | 軽量AIが数値とニュースをもとに初期分類と状況要約を生成 |
| **ウォッチリスト追跡** | ウォッチリストに登録した銘柄の回復率・出来高正常化・新規ニュースを日次で記録 |

### 手動操作（ユーザーが行うこと）

| 操作 | 内容 |
|------|------|
| **一覧確認** | ダッシュボードで急落銘柄の一覧を確認する |
| **フィルタ・ソート** | 分類・ステータス・市場・下落率などで銘柄を絞り込む |
| **詳細確認** | 銘柄をクリックして数値分析・問診ブリーフィングを詳しく読む |
| **診断実行** | 詳細画面の「診断実行」ボタンを押して、高精度AIによる深掘り分析を起動する |
| **ウォッチリスト追加** | 継続観察したい銘柄をウォッチリストに登録する |
| **ウォッチリスト終了** | 観察を終了する場合にクローズ処理を行う |
| **設定変更** | 監視対象市場・AIプロバイダー・自動実行スケジュールなどを変更する |
| **手動パイプライン実行** | 設定画面からパイプラインを任意のタイミングで手動実行する |

## 3. 画面・ページの説明

### 3-1. ダッシュボード（トップページ）

**目的**: 急落銘柄の全体俯瞰と優先銘柄の特定

#### 表示情報

各行に以下の情報が表示されます：

| 項目 | 説明 |
|------|------|
| シンボル / 企業名 | 銘柄コードと会社名 |
| 市場 | US / プライム / スタンダード / グロース |
| 急落日 | 急落が検知された日付 |
| 前日比 | 急落当日の騰落率（例: -8.3%） |
| 週間騰落率 | 急落前後5日間の累積騰落率 |
| 出来高異常度 | 当日出来高 ÷ 過去20日平均（例: 3.2倍） |
| マクロフラグ | 市場全体下落が原因の可能性（🏴フラグ表示） |
| ステータス | 処理段階（検知→分析→問診→診断） |
| AI分類バッジ | 問診結果の分類（事故型/事件型/構造型/マクロ型/不明） |
| 状況要約 | AIが生成した1〜2行の状況説明 |
| 現在の回復率 | 急落日終値から現在までの株価変化率 |

#### フィルタ機能

| フィルタ | 選択肢 |
|---------|--------|
| 期間 | 全期間 / 直近7日 / 直近14日 / 直近30日 |
| ステータス | 全て / 検知 / 分析済 / 問診済 / 診断済 |
| 市場 | 全て / 日経225 / スタンダード / グロース / S&P 500 |
| AI分類 | 全て / 事故型 / 事件型 / 構造型 / マクロ型 / 不明 |
| 最小下落率 | -5% / -8% / -10% / -15% / 任意入力 |
| 最小週間下落率 | 任意入力 |

#### ソート機能

- **検知日順**（デフォルト）: 新しい急落から表示
- **下落率順**: 最大下落銘柄から表示
- **出来高異常度順**: 最も異常な出来高から表示
- **分類順**: 事故型→事件型→構造型→マクロ型→不明の順

---

### 3-2. 詳細画面

**目的**: 個別銘柄の詳細分析確認とAI診断の実行

#### 数値分析セクション

| 指標 | 説明 |
|------|------|
| 前日比 / 週間騰落率 | 急落の大きさ |
| 出来高異常度 | 20日平均比での出来高倍率（高いほど異常） |
| ボラティリティ（年率σ） | 過去1年の価格変動の大きさ |
| 偏差（今回の下落が何σか） | 統計的な異常度 |
| β値 | 市場全体との連動度（1.0 = 市場と同じ動き） |
| セクター騰落率 | 同じセクターのETFの当日変動率 |
| セクター超過下落率 | 銘柄の下落 − セクターの下落（個別要因の大きさ） |
| セクター90日相関 | 同セクターとの連動性（低いほど個別要因が強い） |
| 銘柄固有性スコア | 0〜1（高いほど市場・セクターと無関係な動き） |
| PER / PBR | バリュエーション指標 |
| 自己資本比率 | 財務健全性 |
| 時価総額 | 企業規模 |

#### 関連ニュースセクション

急落前後のニュース記事一覧。タイトル・掲載元・公開日時・前後区分（急落前=原因候補、急落後=反応記事）が表示されます。

#### 問診ブリーフィングセクション

自動生成されるAI初期分析。表示内容：

- **分類バッジ**: 事故型 / 事件型 / 構造型 / マクロ型 / 不明
- **判断根拠**: Q1〜Q3の各軸での判断
- **状況要約**: 何が起きたかの1〜2行の説明

#### 診断ブリーフィングセクション（実行後に表示）

「診断実行」ボタンを押した後、高精度AIが生成する詳細分析。表示内容：

- **分類（最終判定）**: 問診結果を踏まえた再評価
- **事故サブタイプ**: 事故型の場合、詳細な種別
- **経済的堀（moat）評価**: 4軸での企業の競争優位性評価
- **反証**: 「事件である可能性」3点（別の解釈の提示）
- **類似ケース**: 過去の類似急落事例（1〜2件）
- **見落としリスク**: 分析上の注意点
- **確信度**: high / medium / low（根拠も表示）
- **完全ブリーフィング**: 全セクションを含む詳細テキスト

#### 操作ボタン

- **診断実行**: 高精度AI診断を起動（完了まで数分）
- **ウォッチリストに追加**: 継続観察リストへ登録
- **ウォッチリストから削除**: 登録済みの場合に表示

### 3-3. ウォッチリスト

#### 表示情報

| 項目 | 説明 |
|------|------|

| 登録日 / 急落日 | 経過時間の把握 |

- **クローズ**: 観察終了（理由をメモ可能）

## 4. 処理パイプラインの仕組み

DipTriageは、毎朝指定した時刻に以下の6段階処理を自動実行します（手動実行も可能）。

```
Stage 0: 銘柄マスター更新
    ↓
Stage 1: 株価取得・急落検知
    ↓
Stage 2: 数値分析
    ↓
Stage 3a: ニュース収集
    ↓
Stage 3b: 問診（AI初期分析）
    ↓
    ※ここでパイプライン自動処理は終了
    ↓
Stage 4: 診断（ユーザーがボタン押下後に実行）
    ↓
Stage 4.5: ウォッチリスト日次追跡（自動）
```

### Stage 0 — 銘柄マスター更新

監視対象市場（日経225・東証スタンダード・東証グロース・S&P 500）の銘柄リストを取得・更新します。各銘柄について企業名・市場・セクター・セクターETFを管理します。

### Stage 1 — 株価取得・急落検知

前営業日の株価データを取得し、以下の条件で急落銘柄をスクリーニングします：

**検知条件:**

1. 前日比が設定閾値（デフォルト -5%）以下
2. **マクロフィルタ**: 市場全体（日経平均・S&P 500）が -2% 以上下落した日の銘柄には「マクロフラグ」を立てる（市場全体の下落による可能性が高いため）

マクロフラグが立った銘柄は一覧に表示されますが、優先度が低いことが視覚的に示されます。

### Stage 2 — 数値分析

急落銘柄ごとに以下の定量指標を算出します：

| 指標 | 算出方法 |
|------|---------|
| 出来高異常度 | 急落日の出来高 ÷ 過去20日平均出来高 |
| ボラティリティ（年率σ） | 過去1年の日次リターンから標準偏差を算出・年率換算 |
| 偏差 | 今回の下落幅 ÷ 日次標準偏差（今回が何σの異常か） |
| β値 | 過去252日の個別銘柄 vs 市場指数の共分散から算出 |
| セクター超過下落率 | 個別銘柄の下落率 − 同セクターETFの下落率 |
| 90日セクター相関 | 過去90日の個別銘柄 vs セクターETFの相関係数 |
| 銘柄固有性スコア | 上記指標を組み合わせた0〜1のスコア（高いほど個別要因） |
| バリュエーション | PER・PBR・自己資本比率・時価総額（yfinanceより取得） |

### Stage 3a — ニュース収集

Yahoo Finance RSSから各銘柄の関連ニュース記事を取得します。

- **急落前の記事**: 急落の原因候補として表示
- **急落後の記事**: 市場の反応・続報として表示
- **重複除外**: 同一URLの記事は重複として除外
- **収集期間**: 直近数日〜1週間程度（RSSの配信範囲に依存）

### Stage 3b — 問診（AI初期分析）

軽量AIが数値指標とニュース記事を入力として受け取り、以下を自動生成します：

- **急落の直接原因**: 1文で表現
- **3軸判断**: Q1〜Q3（後述）の各回答
- **初期分類**: accident / incident / structural / macro / unknown のいずれか
- **状況要約**: 2〜3文の日本語説明

問診は **数秒〜十数秒** で完了します。

### Stage 4 — 診断（ユーザー起動・オンデマンド）

詳細画面で「診断実行」ボタンを押すと、高精度AI（思考モード有効）がより深い分析を実行します。

- **実行時間**: 数分（AIが内部で深く思考するため）
- **実行中**: 画面上にプログレス表示
- **完了後**: 診断ブリーフィングが画面上に自動表示

詳細内容は [Section 5](#5-ai診断の仕組み) を参照。

### Stage 4.5 — ウォッチリスト日次追跡（自動）

ウォッチリストに登録されている銘柄について、毎日のパイプライン実行時に以下を記録します：

- 当日終値
- 急落時からの回復率
- 当日出来高比率
- 新規ニュース数

これにより、銘柄の回復プロセスを時系列で追跡できます。

## 5. AI診断の仕組み

### 5クラス分類体系

DipTriageは株価急落を以下の5つのクラスに分類します：

| クラス | 日本語 | 定義 | 投資アクション示唆 |
|--------|--------|------|------------------|
| **accident** | 事故型 | 意図しない偶発的なミスや外部イベントによる急落。原因は一時的で回復可能 | 買い場の可能性あり |
| **incident** | 事件型 | 経営者・組織による意図的な悪質行為（不正・詐欺・情報隠蔽）。信頼の毀損 | 回避 |
| **structural** | 構造型 | 悪意はないが、競争力・ビジネスモデル自体が本質的に劣化。自社要因で回復困難 | 回避 |
| **macro** | マクロ型 | 金利変動・地政学リスク・市場全体連動による下落。会社固有のダメージは低い | 条件付き（マクロ判断次第） |
| **unknown** | 不明 | 情報不足または判断軸が定まらないケース | 様子見 |

### 2軸決定木（分類の仕組み）

分類は以下の3つのYes/No質問によって決定します。AIはこの質問に答え、アプリが論理的に分類を導出します（AIが直接分類を「選ぶ」わけではありません）：

```
Q1. 意図的な悪質行為か？
    （不正・詐欺・組織ぐるみの情報隠蔽・意図的なガバナンス悪用）

        YES ──────────────────→ incident（事件型）
         │
        NO
         ↓
Q2. 急落原因は一時的・回復可能か？
    （偶発的ミス・外部イベント・自然災害・一時的な決算ミス・評価調整）

        YES ──────────────────→ accident（事故型）
         │
        NO
         ↓
Q3. 回復困難な原因は自社固有か？
    （競争力低下・ビジネスモデル劣化・市場シェア喪失）

        YES ──────────────────→ structural（構造型）
         │
        NO
         ↓
                               macro（マクロ型）

※ いずれかの軸が判断不能（情報不足）→ unknown（不明）
```

**この設計の利点**: AIが「なんとなく accident っぽい」と判断するのではなく、3つの明確な軸でYes/Noを答えることで、判断根拠が透明になります。また、あいまいな場合は「unknown」に集約されるため、誤分類のリスクが低減されます。

### 問診（Interview）と診断（Diagnosis）の違い

| 比較軸 | 問診 | 診断 |
|--------|------|------|
| **実行タイミング** | 自動（パイプライン内） | 手動（ユーザーがボタン押下） |
| **AIモデル** | 軽量・高速モデル | 高精度・大規模モデル |
| **思考モード** | OFF | ON（内部で深く推論） |
| **所要時間** | 数秒〜十数秒 | 数分 |
| **出力内容** | 初期分類 + 状況要約 | 詳細ブリーフィング全項目 |

### 診断ブリーフィングの全内容

診断実行後に表示されるブリーフィングには以下が含まれます：

#### 1. 分類（最終判定）

問診結果を踏まえた再評価。問診と異なる場合は、診断側の判断が優先されます。

#### 2. 事故サブタイプ（accident の場合のみ）

事故型と判定された場合、その詳細種別を示します：

- **システム障害**: IT障害・クラウド障害など
- **一時的決算ミス**: 会計エラー・見通し誤り
- **製品リコール・品質問題**: 安全性・品質由来
- **経営発言・炎上**: CEOの失言・PR問題
- **自然災害・外的要因**: 地震・台風・サプライチェーン断絶

#### 3. 経済的堀（moat）評価

企業の競争優位性が毀損されているかを4軸で評価します：

| 軸 | 評価値 | 意味 |
|----|--------|------|
| スイッチングコスト | 高 / 中 / 低 | 顧客が他社に乗り換える際のコスト |
| ネットワーク効果 | 有 / 無 | 利用者が増えるほど価値が高まる仕組み |
| 規制参入障壁 | 高 / 中 / 低 | 新規参入を阻む規制・ライセンスの有無 |
| ブランド依存度 | 高 / 中 / 低 | ブランド力が購買行動に与える影響 |
| 総合評価 | テキスト | 上記4軸のサマリーと急落による毀損度 |

#### 4. 反証（事件である可能性）

「事故型と分類したが、実は事件型である可能性」を3点提示します。これはAIの一方向な断定を防ぎ、ユーザーが反証を検討するためのものです。

例:
> 1. 今回の「システム障害」が意図的なデータ改ざんの隠蔽である可能性  
> 2. 経営陣が障害の深刻さを事前に把握しながら情報開示を遅らせた可能性  
> 3. 類似障害が過去にも発生しており、組織的な品質管理問題である可能性

#### 5. 類似ケース

過去に類似した急落事例（1〜2件）を参照します。回復したか否かも含めて示します。

#### 6. 見落としリスク

今回の分析で情報が不足している点や、追加確認すべき点を提示します。

#### 7. 確信度

AIの分析に対する自己評価：

- **high**: 根拠が明確で分類に迷いなし
- **medium**: 一部不確実性あり
- **low**: 情報不足または複数の解釈が可能

確信度が **low** の場合は、independent に調査することを推奨します。

## 8. 設計思想

### 1. ブリーフィング型: AIは判断しない

DipTriageのAIは「買え」「売れ」と言いません。AIの役割は、**投資判断の根拠を整理・提示すること**です。これにより：

- ユーザーは自分の頭で考える習慣を維持できる
- AIの誤判断による損失リスクを低減できる
- 分析の透明性が確保され、学習効果がある

### 2. 反証ステップの強制

診断では必ず「事件である可能性」を3点生成します。これは：

- AIが「事故型」と断定しても、ユーザーに疑いの目を向けさせる
- LLMが一方向に偏った結論を出すバイアスを軽減する
- 投資判断において最悪ケースを想定する習慣を促す

### 3. Yes/No決定木: 分類の根拠を明確化

AIに「この急落はaccidentだ」と直接選ばせるのではなく、3つのYes/No質問に答えさせます。これにより：

- 分類の**根拠がテキストとして残る**（なぜaccidentか）
- 「あいまい」な判断は **unknown** に集約される
- AIの出力が整合しない場合も、優先規則で一貫した分類が得られる

### 4. ローカルLLM対応

デフォルトはOllama（ローカルAI）で動作します。これにより：

- API料金がゼロ
- 銘柄情報・分析内容が外部サーバーに送られない（プライバシー保護）
- インターネット環境に依存しない

### 5. 経過観察データの蓄積

ウォッチリストで記録した回復率・出来高・ニュースのデータは、将来的な「分類結果の検証・後学習」に活用できる形式で保存されています。将来的には「事故型と分類した銘柄は30日後に何%回復したか」を定量的に評価できるようになります。

## 9. 用語集

| 用語 | 説明 |
|------|------|
| **急落イベント（Dip Event）** | 前日比 -5% 以上の下落として検知された1件の急落 |
| **問診（Interview）** | 軽量AIによる初期分析。自動実行・数秒で完了 |
| **診断（Diagnosis）** | 高精度AIによる詳細分析。手動実行・数分かかる |
| **マクロフラグ（Macro Flag）** | 市場全体の下落が原因の可能性を示すフラグ |
| **銘柄固有性スコア** | 急落が市場・セクターと無関係な個別要因によるものかを示す0〜1のスコア |
| **出来高異常度** | 急落日の出来高 ÷ 過去20日平均。3倍以上なら異常とみなされる |
| **β値（ベータ）** | 市場全体との連動性。1.0 = 市場と同じ動き |
| **セクター超過下落率** | 個別銘柄の下落幅 − 同セクターETFの下落幅 |
| **ウォッチリスト（Watchlist）** | 診断後の銘柄を継続観察するリスト |
| **経済的堀（Moat）** | 企業の競争優位性（スイッチングコスト・ネットワーク効果・規制障壁・ブランド） |
| **事故型（accident）** | 偶発的・一時的な原因による急落。回復可能性が高い |
| **事件型（incident）** | 意図的な悪質行為・不正による急落。信頼毀損 |
| **構造型（structural）** | 競争力・ビジネスモデルの本質的な劣化による急落 |
| **マクロ型（macro）** | 金利・地政学・市場全体の変動による急落 |
| **不明（unknown）** | 判断材料不足または分類軸が定まらないケース |
| **Ollama** | ローカルPC上でAIモデルを動かすソフトウェア |
| **Groq** | 高速AI推論を提供するクラウドAPIサービス |
| **APScheduler** | バックグラウンドで定時処理を実行するスケジューラー |
| **確信度（Confidence）** | AIが自分の分析にどれだけ自信を持っているかの評価（high/medium/low） |
