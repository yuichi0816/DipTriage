# DipTriage 簡易マニュアル

**目的**: 株価急落銘柄が「事故（一時的）」か「事件・構造問題（本質的）」かを判断する材料を提示するツール。最終判断は人間が行う。

---

## 起動手順

### 1. Ollama を起動する（LLM が必要な場合）

```bash
# Ollama サービスを起動
ollama serve

# 必要なモデルを確認（未 pull の場合は pull）
ollama list
ollama pull qwen3.5:9b    # 問診用（速い）
ollama pull qwen3.6:35b   # 診断用（精度高い・数分かかる）
```

> **Groq を使う場合**: Ollama 不要。設定画面で LLM プロバイダーを「Groq」に変更し、API キーを入力する。

### 2. Web サーバーを起動する

```powershell
# 通常運用（同一PCからのみアクセス。Tailscale 経由は `tailscale serve 8000` を併用）
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000

# 開発時（コード編集の自動リロード付き）
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload --reload-exclude ".claude" --reload-exclude "*.log" --reload-exclude "data"
```

> **セキュリティ注意**: `--host 0.0.0.0` は LAN 全体に無認証で公開されるため使用しないこと。
> LAN 内の他端末からアクセスしたい場合は `.env` に `DIPTRIAGE_PASSWORD` を設定して
> Basic 認証を有効化した上で、Tailscale IP（100.x.x.x）にバインドする。

ブラウザで **http://localhost:8000** を開く。

## 日次ワークフロー

```
毎朝 7:00 に自動実行（設定で変更可）
   ↓
① 急落検知（前日比 -5% 以下 かつ マクロ要因でない銘柄）
   ↓
② 数値分析（出来高・β値・PER/PBR・セクター相関）
   ↓
③ ニュース取得（Yahoo Finance RSS）
   ↓
④ 問診 LLM → 5クラス初期分類（事故型 / 事件型 / 構造型 / マクロ型 / 不明）
   ↓
   ※ 自動処理ここまで
   ↓
⑤ 診断 LLM → オンデマンド実行（ユーザーが詳細画面のボタンから手動起動）
```

### 5クラス分類

| クラス | 意味 | 投資示唆 |
|--------|------|---------|
| **事故型** | 偶発的ミス・外部イベント（一時的） | 買い場の可能性あり |
| **事件型** | 不正・詐欺・意図的な悪質行為 | 回避 |
| **構造型** | 競争力・ビジネスモデルの本質的劣化 | 回避 |
| **マクロ型** | 金利・地政学・市場全体連動 | 条件付き |
| **不明** | 判断材料不足 | 様子見 |

### 手動実行

```bash
# 本日分のパイプラインを手動実行
uv run python scripts/run_pipeline_once.py

# 過去日付でバックフィル（例: CrowdStrike 事例）
uv run python scripts/backfill.py 2024-07-19
```

設定画面の「パイプラインを今すぐ実行」ボタンからも手動実行できる。

## 画面説明

### ダッシュボード（/）

急落検知済みのイベント一覧。

| 表示項目 | 内容 |
|---------|------|
| バッジ | AI分類（事故型 / 事件型 / 構造型 / マクロ型 / 不明）+ 色分け |
| ステータス | detected → analyzed → interviewed → diagnosed |
| 前日比 / 週間騰落率 | 急落の大きさ |
| 出来高異常度 | 20日平均比（例: 3.2倍） |
| マクロフラグ | 市場全体の下落が原因の可能性（フラグ表示） |
| 状況要約 | AIが生成した1〜2行の概要 |
| 回復率 | 急落日終値から現在までの株価変化 |

#### フィルタ

ダッシュボード上部のフィルタバーで以下を絞り込める：

| フィルタ | 選択肢 |
|---------|--------|
| 期間 | 全期間 / 7日 / 14日 / 30日 |
| ステータス | 全て / 検知 / 分析済 / 問診済 / 診断済 |
| 市場 | 全て / 日経225 / スタンダード / グロース / S&P 500 |
| AI分類 | 全て / 事故型 / 事件型 / 構造型 / マクロ型 / 不明 |
| 最小下落率 | -5% / -8% / -10% / -15% / 任意 |
| ソート | 検知日 / 下落率 / 出来高異常度 / 分類順 |

---

### 詳細画面（/dip/{id}）

銘柄行をクリックすると表示。

#### 数値分析セクション

- 前日比 / 週間騰落率
- 出来高異常度（20日平均比）
- ボラティリティ（年率σ）と偏差（今回が何σか）
- β値・セクター超過下落率・90日セクター相関
- 銘柄固有性スコア（0〜1）
- PER / PBR / 自己資本比率 / 時価総額

#### 問診ブリーフィング（自動生成）

- AI分類バッジ（5クラス）
- Q1〜Q3の判断根拠
- 状況要約（2〜3文）

#### 診断ブリーフィング（手動実行）

1. **「診断を実行」ボタン**をクリック
2. 「分析中（数分かかります）...」と表示される
3. 完了すると以下が表示される：
   - 分類（最終判定）
   - 事故サブタイプ（事故型の場合）: システム障害 / 一時的決算ミス / 製品リコール / 経営発言炎上 / 自然災害・外的要因
   - moat 評価（スイッチングコスト / ネットワーク効果 / 規制障壁 / ブランド依存度）
   - **反証3件**（「事件である可能性」）
   - 類似ケース（1〜2件）
   - 見落としリスク
   - 確信度（high / medium / low）

#### ウォッチリスト操作

- 詳細画面から「ウォッチリストに追加」ボタンで登録
- 登録済みの場合は「ウォッチリストから削除」ボタンが表示

---

### ウォッチリスト（/watchlist）

診断後の銘柄の経過観察ページ。

| 表示項目 | 内容 |
|---------|------|
| 銘柄 / 登録日 | 基本情報 |
| 急落時価格 → 現在価格 | 株価の推移 |
| 回復率 | 急落時比の株価回復度（例: +12.5%） |
| 出来高比率 | 現在 ÷ 急落時（正常化の目安） |
| 新規ニュース数 | 登録後に取得された新着記事数 |
| AI分類 | 診断時のバッジ |

操作:
- **クローズ**: 観察終了
- 銘柄クリックで詳細画面へ

---

### 設定パネル（ダッシュボード左）

ダッシュボード左側のパネルから設定を変更できる。変更後は「保存」ボタンを押す。

#### 自動取得

| 項目 | 説明 |
|------|------|
| 自動取得 ON/OFF | パイプラインの自動実行を有効/無効化 |
| 実行時刻（時:分） | 毎日何時に自動実行するか（JST） |
| 急落スキャン日数 | 何日前までの銘柄をスキャンするか |
| ニュース更新日数 | 何日前までの銘柄のニュースを更新するか |

#### 取得対象市場

チェックボックスで ON/OFF:
- 日経225（プライム）
- 東証スタンダード
- 東証グロース
- S&P 500

#### LLM プロバイダー

| 選択肢 | 説明 |
|--------|------|
| **Ollama**（デフォルト） | ローカル PC で動作。API 料金不要・プライバシー保護 |
| **Groq** | クラウド API。高速・高性能だが API キーが必要 |

Groq を選んだ場合は API キーと使用モデルを入力する。

#### 手動操作ボタン

- **パイプラインを今すぐ実行**: 自動実行を待たずに即時実行
- **ニュースを今すぐ更新**: ニュース収集だけを即時実行

## 環境変数（.env ファイルで設定可）

| 変数 | デフォルト | 説明 |
|------|-----------|------|
| `OLLAMA_HOST` | `http://localhost:11434` | Ollama のエンドポイント |
| `OLLAMA_MODEL_INTERVIEW` | `qwen3.5:9b` | 問診モデル |
| `OLLAMA_MODEL_DIAGNOSIS` | `qwen3.6:35b` | 診断モデル |
| `THRESHOLD_DIP_PCT` | `-5.0` | 急落検知の閾値（%） |
| `MACRO_FILTER_PCT` | `-2.0` | マクロフィルタの閾値（%） |
| `DB_PATH` | `data/diptriage.db` | SQLite DB のパス |
| `PIPELINE_HOUR` | `7` | 自動実行の時刻（時） |

設定例（`.env`）:
```
OLLAMA_HOST=http://192.168.1.100:11434
OLLAMA_MODEL_DIAGNOSIS=qwen3.6:35b
THRESHOLD_DIP_PCT=-7.0
```

> **注意**: 実行時刻・LLM プロバイダーなど多くの設定は Web UI の設定パネルから変更できる。`.env` は起動時のデフォルト値として機能する。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| 診断ボタンが表示されない | status が interviewed/diagnosed でない | 問診が完了するまで待つ |
| 「診断に失敗しました」 | Ollama が起動していない | `ollama serve` を実行 |
| 問診で止まる（interviewed にならない） | Ollama 未起動 / モデル未 pull | `ollama list` で確認・pull |
| ダッシュボードが空 | データ未投入 | `scripts/backfill.py` でテストデータを投入 |
| マクロフラグのイベントが多い | 市場全体が大きく下落している | 正常動作（個別要因のみ分析対象） |
| 分類が「不明」ばかり | ニュース不足 / モデル精度の問題 | Groq に切り替えて再実行 |
| Groq で「APIキーエラー」 | キー入力ミス / 権限不足 | 設定パネルでキーを再入力 |
