DipTriage マニュアル

株価急落銘柄が「事故（一時的）」か「事件・構造問題（本質的）」かを判断する材料を提示するツール。最終判断は人間が行う。

1. 起動手順

1-1. Ollama を起動する（LLM が必要な場合）

# Ollama サービスを起動
ollama serve

# 必要なモデルを確認（未 pull の場合は pull）
ollama list
ollama pull qwen3.5:9b    # 問診用（速い）
ollama pull qwen3.6:35b   # 診断用（精度高い・数分かかる）
Groq を使う場合: Ollama 不要。設定パネルで LLM プロバイダーを「Groq」に変更し、API キーを入力する。

1-2. Web サーバーを起動する

uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload \
  --reload-exclude ".claude" --reload-exclude "*.log" --reload-exclude "data"

ブラウザで http://localhost:8000 を開く。

2. 日次ワークフロー

毎朝 7:00 に自動実行（設定で変更可）

↓

① 急落検知（前日比 -5% 以下 かつ マクロ要因でない銘柄）

↓

② 数値分析（出来高・β値・PER/PBR・セクター相関）

↓

③ ニュース取得（Yahoo Finance RSS）

↓

④ 問診 LLM → 5クラス初期分類

↓ ※ 自動処理ここまで

⑤ 診断 LLM → 詳細画面のボタンから手動起動

5クラス分類

クラス 意味 投資示唆
事故型 偶発的ミス・外部イベント（一時的） 買い場の可能性あり
事件型 不正・詐欺・意図的な悪質行為 回避
構造型 競争力・ビジネスモデルの本質的劣化 回避
マクロ型 金利・地政学・市場全体連動 条件付き
不明 判断材料不足 様子見

手動実行

# 本日分のパイプラインを手動実行
uv run python scripts/run_pipeline_once.py

# 過去日付でバックフィル（例: CrowdStrike 事例）
uv run python scripts/backfill.py 2024-07-19

設定パネルの「パイプラインを今すぐ実行」ボタンからも手動実行できる。

詳細画面（/dip/{id}）

銘柄行をクリックすると表示。

数値分析セクション

  • 前日比 / 週間騰落率
  • 出来高異常度（20日平均比）
  • ボラティリティ（年率σ）と偏差（今回が何σか）
  • β値・セクター超過下落率・90日セクター相関
  • 銘柄固有性スコア（0〜1）
  • PER / PBR / 自己資本比率 / 時価総額

問診ブリーフィング（自動生成）

  • AI分類バッジ（5クラス）
  • Q1〜Q3の判断根拠
  • 状況要約（2〜3文）

診断ブリーフィング（手動実行）

  1. 「診断を実行」ボタンをクリック
  2. 「分析中（数分かかります）...」と表示される
  3. 完了すると以下が表示される
  • 分類（最終判定）
  • 事故サブタイプ（事故型の場合）: システム障害 / 一時的決算ミス / 製品リコール / 経営発言炎上 / 自然災害・外的要因
  • moat 評価（スイッチングコスト / ネットワーク効果 / 規制障壁 / ブランド依存度）
  • 反証3件（「事件である可能性」）
  • 類似ケース（1〜2件）
  • 見落としリスク
  • 確信度（high / medium / low）

変数 デフォルト 説明

OLLAMA_MODEL_INTERVIEWqwen3.5:9b問診モデル

THRESHOLD_DIP_PCT-5.0急落検知の閾値（%）
MACRO_FILTER_PCT-2.0マクロフィルタの閾値（%）
DB_PATHdata/diptriage.dbSQLite DB のパス
PIPELINE_HOUR7自動実行の時刻（時）

設定例（.env）:

OLLAMA_HOST=http://192.168.1.100:11434
OLLAMA_MODEL_DIAGNOSIS=qwen3.6:35b
THRESHOLD_DIP_PCT=-7.0
注意: 実行時刻・LLM プロバイダーなど多くの設定は Web UI の設定パネルから変更できる。.env は起動時のデフォルト値として機能する。

5. トラブルシューティング

症状 原因 対処
診断ボタンが表示されない status が interviewed/diagnosed でない 問診が完了するまで待つ（下記「分析済で止まる」も参照）
「分析済」のまま問診が実行されない ① マクロ変動フラグが立っている、または ② ニュース記事が取得できなかった ① マクロ時は正常動作。② 「ニュース更新」ボタンで再取得を試みる
「診断に失敗しました」 Ollama が起動していない ollama serve を実行
問診で止まる（interviewed にならない） Ollama 未起動 / モデル未 pull ollama list で確認・pull
ダッシュボードが空 データ未投入 scripts/backfill.py でテストデータを投入
マクロフラグのイベントが多い 市場全体が大きく下落している 正常動作（個別要因のみ分析対象）
分類が「不明」ばかり ニュース不足 / モデル精度の問題 Groq に切り替えて再実行
Groq で「APIキーエラー」 キー入力ミス / 権限不足 設定パネルでキーを再入力
